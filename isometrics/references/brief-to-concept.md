# From a brief to three concepts

Most briefs are a word or two: "gallery isometrics", "billing", "an empty
team page". This file is how you get from that to three concepts worth
choosing between, and what a good table looks like.

## 1. Read the brief: subject, use, message

| Brief says | Subject | Likely uses |
| --- | --- | --- |
| a product area ("gallery", "billing", "team") | the area's main thing | empty (most often), blocked |
| a state ("no results", "offline", "locked") | the state's thing | that state |
| an object ("a lock", "a bell") | the object | ask yourself what it's *for*; pick the use that fits best |
| a feature card ("for our sync feature") | the feature's action | spot illustration (the beat shows the feature working) |

The **message** is one sentence the state says to the person in front of
it. Write it before you think about objects: "You haven't added any photos
yet." / "You don't have access to this album." / "No photos match these
filters."

## 2. Find objects that carry the message

For each candidate object ask:

- **Is it the thing, a container of the thing, or a tool for the thing?**
  Containers are the strongest for empty states (an album, a folder, a
  box: empty is visible). Tools are strongest for "nothing found" (a
  magnifier, a filter funnel). Barriers are strongest for blocked (a lock,
  a switch, a cone, a plug).
- **Can it move in a way that says the message?** Empty → it opens and
  shows nothing; blocked → it tries and stops; nothing found → it looks
  and pauses; all clear → it settles, clicks in, rings once.
- **Does it pass the four tests** (SKILL.md stage 2): reads in outline at
  120 px, rounded beats boxy, one object, the beat says the message.

Throw out: things that need text to be recognised (a "report"), things
that need colour (a traffic light), scenes (a desk with things on it),
logos and brand objects (a specific phone, a specific app icon), and
anything that only reads in perspective (roads, rooms).

## 3. Write the table

Three rows, different objects, different beats. ★ your pick, with one line
saying why. Keep cells short; the user decides in five seconds.

### Worked: "gallery isometrics"

Subject: photos. Uses: empty (no photos yet) or blocked (private album).

| | Object | Message (heading) | The one beat |
|---|---|---|---|
| A ★ | A stack of three photo prints | No photos yet | The top print slides off the stack to the right, settles straight and shows a blank print |
| B | A photo album | Your album is empty | The cover swings open (≤ 100°) and settles; the first page is blank |
| C | A film camera | Nothing captured yet | The shutter button presses, the lens ring flicks once, it settles |

★ A: the empty print *is* the message, and a slide is the calmest move.

### Worked: "billing"

## 4. When the brief is clear

If the brief already names an object and a state ("an empty-cart state
with a shopping bag"), don't make a table: state the object, the message,
the beat and the copy in four lines, and build.

## 5. When the user rejects all three

Ask which part missed: the object, the message, or the beat. Change only
that. Never show the same object twice in a row.
